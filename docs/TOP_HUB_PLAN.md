# トップページ再設計 — ハブ構成・文言・UI/UX 指針

更新日: 2026-11-22

## この文書の役割

トップ（`/`）を **「設計と一緒に、サンプルで試せる」** を軸とした **薄いハブ** に作り替えるための、構成・確定文案・UI/UX の設計メモ。

実装の正本はコード。本書は実装前〜実装中の設計参照用。サイト全体の最小仕様は引き続き `docs/PRODUCT_SPEC.md` を参照する。実装完了後は `PRODUCT_SPEC.md` のトップ説明を本方針に合わせて更新する。

## 背景と方針

### 課題

- 現行トップ（`demo-first`）は、理由・デモ・問い合わせ・LAB を 1 スクロールに詰め込んでおり、PC 向け 2 列レイアウトとの相性も悪い。
- サービスページ（`ServicesLp` / `svc-lp`）側でデザインと説得力が作り込まれており、トップだけ別 UI を磨き続ける効果は限定的。
- スマホ閲覧前提では、サービス LP と同じ **縦積み・狭いカラム** の方が一貫して読みやすい。

### 決定事項

| 項目 | 方針 |
| --- | --- |
| トップの使命 | 30 秒で ideal のやり方を掴み、**深い話は各ページへ進む** |
| デザイン | **`svc-lp` に統一**（`app/services` と同系統） |
| コンセプト | **設計と一緒に、サンプルで試せる** |
| 情報量 | トップは薄く。詳細は `/services`・デモ導線・その他ページ |
| 旧トップ | `DemoFirstReason` 全文・8 枚デモ一覧などはトップから外す |

### `/` と `/services` の住み分け

- **`/`** … 地図・短いコピー・入口カード（スクロール短め）
- **`/services`** … 相談・設計〜製作・ステップ・事例・ROI（現行 `ServicesLp` のまま本体）

トップにサービス LP の半分を複製しない（SEO 重複・迷い防止）。

## コンセプト（伝えること）

### キャッチコピー

**設計と一緒に、サンプルで試せる。**

### サブ（ヒーロー直下・任意）

Web・業務アプリ・AI を、触れる形から一緒に進めます。

### リード（2〜3 文・`svc-body` 想定）

要件定義を紙で何往復もする前に、動くサンプルで制作イメージと設計の解像度を上げます。小さな単位で段階的に開発し、都度確認しながら手戻りとリスクを抑えます。サンプルで早くズレに気づくから、全体として速く・安全に進められます。

### 補足メッセージ（誤解防止・サービス側でも言い換え可）

- 「サンプル」は資料の代替ではなく、**相談・設計の範囲で触れる試作**（サービス LP の「試作・動くデモ」と同義で読ませる）。
- 「スピーディ」は手順を飛ばす速さではなく、**手戻りを減らすことによる速さ**。

## ページ構成（セクション順）

全体ラッパー: `div.svc-lp`（必要なら `ServicesLpMotion` で `data-ready` / 入場演出。トップは短いので **Motion は軽め or 省略可**）。

```
svc-lp
└ svc-col
   1. Ribbon（任意・トピック帯）
   2. Hero（about 相当）
   3. コンセプト 3 点
   4. 入口ハブカード
   5. デモチラ見せ（任意・薄く）
   6. CTA（問い合わせ）
```

フッターは全站共通のまま。トップ専用で `DemoFirstLab` の長文ブロックは載せず、LAB はハブカードから `/lab` へ。

### デモ・記事の扱い

| コンテンツ | トップ | 本体 |
| --- | --- | --- |
| 代表デモ | **2〜3 件 +「もっと見る」** | `/services#examples` または今後のデモ一覧 |
| 理由 3 図セクション | **載せない** | `/services` の thinking / about |
| 記事 | ハブカードから `/articles` | 一覧・詳細は記事ページ |
| LAB | ハブカードから `/lab` | `/lab`・計器は既存 |

**デモ URL 方針（要最終決定）**

## 確定文案一覧

### 1. ヒーロー

| 要素 | 文案 |
| --- | --- |
| Eyebrow | ideal |
| 見出し（`LpHeading`・行配列） | `['設計と一緒に、', 'サンプルで試せる。']` |
| 本文 | 上記「リード」 |
| 主 CTA | サービスを見る → `/services` |
| 副 CTA | サンプルを触る → デモ導線（URL は上記方針） |

旧ヒーロー「触って試せるシステム開発」は、副 CTA ラベル・デモチラ見せ見出しなど **サブコピーとして再利用可**。

ヒーロー背景: サービス LP の about に近い **白地 `svc-w`**。現行トップの全面写真ヒーロー（`PageHero` + `top.png`）はトップでは使わない方針（`svc-lp` と統一）。写真を足す場合は `ServicesLpCarousel` 相当の **カード内ビジュアル** に限定。

### 2. コンセプト 3 点

各ブロック: `Eyebrow`（省略可）+ 短い `h3` + 1 文 `svc-body`。リンクはカード全体または `svc-btn` テキストリンク。

**1 — 設計を一緒に**

- 本文: 何から着手するか、どこまでを一期にするかを、現場運用まで含めて一緒に設計します。
- Link: サービスの全体像を見る → `/services`

**2 — サンプルで試す**

- 本文: 要件が固まりきる前から、触れるサンプルで方向と質感を合わせます。
- Link: サンプルを見る → デモ導線

**3 — 小さく段階的に**

- 本文: 小さく試し、反応を見てから本実装へ。都度リスクを確認しながら進めます。
- Link: 進め方を見る → `/services` 内ステップ（アンカーは実装時に既存 id に合わせる）

### 3. 入口ハブカード（メイン導線）

`svc-wrap` 内の縦並びカード（新規 `HomeHubCard` 想定）。サービス LP の about カード／事例タブの **角丸・枠・フットラベル** を参考にし、1 カード = 1 行リード + 矢印。

| ラベル | リード（1 行） | href |
| --- | --- | --- |
| サービス | 相談・設計から Web・アプリ・AI まで | `/services` |
| 動くデモ | 触って確かめるサンプル | デモ導線 |
| 進め方 | 設計から段階的に進める流れ | `/services`（ステップ節） |
| 現場の記事 | 業界・悩み別の読み物 | `/articles` |
| LAB | 思想と研究 | `/lab` |
| 問い合わせ | まだ言葉になっていなくても相談可 | `/contact` |

### 4. デモチラ見せ（任意セクション）

## UI/UX 設計（サービスページ準拠）

### 参照実装

| 用途 | 参照 |
| --- | --- |
| ページ骨格 | `components/services/hub/lp/ServicesLp.tsx` |
| パーツ | `components/services/hub/lp/ServicesLpParts.tsx`（`Eyebrow`, `LpHeading`, `Ribbon`, `BrandRibbon`） |
| スタイル | `app/globals.css` の `.svc-lp` 以下 |
| データ分離の例 | `data/services/hub.ts` → 新規 `data/home/hub.ts`（仮） |

### レイアウト原則

1. **スマホファースト**: コンテンツ幅は `.svc-col`（max 640px / lg で `min(720px, calc(100% - 440px))`）。PC 専用 2 列（理由の図＋テキスト）はトップでは採用しない。
2. **1 セクション = 1 役割**: スクロール区切りは `svc-sec` の縦 padding（72px 基準）。交互の全幅色帯（旧 `bandBlue`）は使わない。
3. **背景の切り替え**: 基本 `svc-w`（白）。強調ブロックのみ `svc-d`（ナイト）。ヒーローと CTA で交互にしても **セクション数は最小**（例: Hero 白 → ハブ白 → CTA 白、または CTA 前だけ `svc-d` 1 枚）。
4. **日本語折り返し**: 見出しは `LpHeading` の **行配列** で意味の切れ目のみ改行。見出し用 `max-width: N em` は使わない（ワークスペースルール）。

### セクション別デザイン

#### Ribbon（任意・セクション 1）

- **Component**: `Ribbon` または `BrandRibbon`
- **内容案**: `servicesLpTopics` の一部、またはトップ専用  
  `['設計と一緒に', 'サンプルで試す', '段階的に開発', 'Web', 'アプリ', 'AI']`
- **UX**: 装飾＋キーワードの印象付け。`aria-hidden` 相当は `Ribbon`、意味を持たせるなら `BrandRibbon` + `aria-label`
- **旧マーキー**: `DemoFirstMarquee`（`df-marquee`）は廃止し、ここに一本化

#### Hero（セクション 2）

- **Class**: `svc-w svc-sec`（about 第 1 屏に近い）
- **Parts**: `Eyebrow` + `LpHeading as="h1"` + `p.svc-body` + 縦並び `svc-btn` 2 本（sm 以上で横並び可。サービス LP のボタンスタイル踏襲）
- **Motion**: `LpHeading` に `svc-rv`（`ServicesLpMotion` 利用時）
- **余白**: `head` はサービス about と同程度の `margin-bottom`（目安 24〜48px）

#### コンセプト 3 点（セクション 3）

- **Class**: `svc-w svc-sec`（padding ややタイトでも可）
- **UI 案 A（推奨）**: 3 つの枠付きブロックを縦積み。枠は `border: 1px solid var(--s-line)`、`border-radius` は LP カードに合わせる
- **UI 案 B**: 番号なしの短いリスト + テキストリンク（より薄いハブ）
- **タップ領域**: カード全体を `Link` にし、最低 44px 行高を確保

#### 入口ハブ（セクション 4）

- **Class**: `svc-w svc-sec`
- **UI**: 6 枚のリンクカード。`servicesLpAbout.cards` の **フットラベル + 1 行** の密度を参考
- **状態**: hover で枠色 `var(--s-brand)` 寄り、矢印はサービス LP の `btn-arrow` / フッター「見る →」系
- **情報密度**: タイトル + 1 行のみ。本文段落は入れない

#### デモチラ見せ（セクション 5・任意）

- **Class**: `svc-w svc-sec` または薄い `background: var(--s-tint)` の 1 ブロックのみ
- **UI**: 横スクロール 2〜3 枚、または縦積みコンパクトカード。フル `TopFeaturedDemoShowcase` は使わない
- **目的**: 「サンプルで試せる」の体感。詳細は飛ばす

#### CTA（セクション 6）

- **Class**: `svc-w svc-sec`（サービス `ServicesLpContact` と同型を簡略化）
- **フォーム**: トップでは **省略可**（ボタンのみ `/contact`）。フォームを載せる場合は LP と同じ prefill 動作を踏襲

### 右カラム（デスクトップ）

サービス LP と同様、1024px 以上で **右に TOC や装飾カラム** がある場合は、トップでは **TOC なし**（`ServicesLpToc` 相当は不要）。`svc-col` 中央の一本カラムのみでよい。

### 入場演出

- `ServicesLpMotion` を使う場合: ルートに `id="home-hub"` を付与し、`data-ready` 後に `svc-rv` / `svc-obs` を表示
- トップが短いため、**全要素に delay を振らず** Hero とハブカードの 2 段だけでも可

### アクセシビリティ

- 見出し階層: `h1` は Hero 1 つのみ。セクションは `h2` / `h3`
- ハブカード: 見出し + 説明がリンク名に含まれるよう `aria-label` または視覚テキストで完結
- Ribbon: 装飾のみなら `aria-hidden`、意味があるなら `BrandRibbon` パターン
