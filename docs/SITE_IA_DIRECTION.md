## 0. 一文の結論

**説明の正本は業種LP（W型）1箇所にする。**  
トップは入口、外部デモは体験、導入の流れは共通手順、デモ一覧は索引、活用イメージ詳細は廃止してLPへ吸収する。

LPを入れる本当の効果は「ページを増やすこと」ではなく、**説明を1箇所に集めて他を痩せさせること**である。

---

## 1. いま壊れていること（確定診断）

同じ話が最大3箇所にあり、相互リンクでさらに分岐している。

| 面 | 例URL | いま起きていること |
|---|---|---|
| トップ4カード | `/` | 紹介 + 流れ誘導 + 外部デモ直行が同居 |
| デモ一覧 / 部品詳細 | `/ai-capability-gallery/...` | 触る + 薄い説明 + 次へCTA多数 |
| 活用イメージ | `/cases/industries/...` | 業務Before/Afterの説明（LPと重複） |
| 既存 `/demo/{slug}` | 例: `/demo/voice-to-structured` | いちばん良い説明なのに下層・脇導線 |

典型の混線例:

```text
/ai-capability-gallery
  → /cases/industries/care-voice-records
  → /ai-capability-gallery/voice-to-structured
  → /demo/voice-to-structured または 再び cases
```

訪問者には「体験 / 詳しく / 活用イメージ / 流れを見る」の差が分からない。  
**誰も見ない下層に良い説明がある**状態になっている。

## 2. 確定する公開導線（2段 + 出口）

```text
TOP 業種カード（入口）
  ├─ ［詳しく見る］ → /demo/{industry-or-offer-slug}   ← 業種LP（説明の正本）
  └─ デモを直接開く ↗ → 外部デプロイ済みデモ         ← 体験の最短経路

業種LP
  ├─ 体験（外部デモ / 必要なら埋め込み）
  ├─ 説明すべて（旧casesの中身を含む）
  ├─ B12 進め方（要約）→ /how-we-work（共通手順のみ）
  ├─ 試算（ROI）
  └─ 相談（/contact）
```

公開サイトで訪問者に見せる「ページ種類」はこれ以上増やさない。

| 種類 | 役割 | 主CTA |
|---|---|---|
| TOP業種カード | 自分の業種を見つける | 詳しく見る（LP） |
| 業種LP（W型） | 説明の唯一の正本 + 体験導線 | 試算 / 相談 |
| 外部デモ | 動かす・商談で見せる | （LPへ戻る / 相談） |
| `/how-we-work` | idealとの導入手順（共通） | 相談 / 見積 |
| デモ一覧 | 索引のみ（説明を書かない） | LPへ |
| 相談 / 試算 | 出口 | 完了 |

## 3. ページ役割表（書いてよいこと / 書いてはいけないこと）

### 3.1 TOP 業種カード（メイン4つ）

| 書いてよい | 書いてはいけない |
|---|---|
| 業種名 | Before/After全文 |
| 課題2行 / 解決2行 | FAQ、進め方、ROIの詳細 |
| 主ボタン1つ「詳しく見る」 | 「流れを見る」「詳しく知る」「活用イメージ」など説明系の第二ボタン |
| 補助テキスト「デモを直接開く ↗」 | 部品ギャラリーへの主誘導 |

ボタン規則（確定）:

```text
［ 詳しく見る → ］     ← ボタンはこれだけ（→ 業種LP）
デモを直接開く ↗       ← 小さいテキストリンク（外部デモ）
```

「流れを見る」はカードから消す。流れはLPのB12と `/how-we-work` に置く。  
直行リンクは残す（商談中・再訪の最短経路のため）。

### 3.2 業種LP（W型）— 説明の正本

| 書いてよい | 書いてはいけない |
|---|---|
| B00–B14 相当の説得（v1定義に準拠） | 他ページへの「説明の続きはこちら」連発 |
| 旧casesの業務変化（B04/B05/B08へ吸収） | 部品デモのカタログ説明を本線に置くこと |
| 外部デモへの体験CTA | 金額ロジックの独自複製（ROI Config参照） |
| B12要約 + `/how-we-work` へのリンク | cases詳細を第二の説明ページとして残すこと |

URL方針:

- 公開の主着地は `/demo/{slug}`
- **W型（業種/オファー）** をTOPカードの着地にする（後述 §5）
- 既存の部品系 `/demo/{capability-slug}` は営業送付・F型用に残してよいが、TOP本線からは外す

### 3.3 `/how-we-work`（導入の流れ）

| 書いてよい | 書いてはいけない |
|---|---|
| 相談→概算→PoC→本番…の共通手順 | 業種別Before/After |
| 「どこまで無償か」の共通説明 | cases相当の長文ストーリー |
| LPのB12からの詳細リンク先 | 「デモ別の活用イメージで詳しく読む」を本線にすること |

**禁止パターン（明示的に不採用）:**

```text
LP → 導入の流れ → /cases/industries/... の説明ページ
```

これは説明を再分散させる。導入の流れは手順専用に固定する。

### 3.4 デモ一覧 `/ai-capability-gallery`

| 変更後の役割 | やること |
|---|---|
| 索引 | タイトル程度。説明文・活用ストーリーを書かない |
| 遷移 | 対応する業種LP（または将来のF型LP）へ |
| 部品詳細ページ | 独立詳細としての露出を止める（§6） |

### 3.5 活用イメージ `/cases/...`

| 変更後 | 扱い |
|---|---|
| 詳細ページ | **廃止対象**。中身は業種LPの B04（コストの正体）/ B05（効く条件）/ B08（結果イメージ）等へ吸収 |
| 一覧 | 過渡期は業種索引として残してもよいが、最終的にはTOPまたはLPへ統合 |
| URL | 廃止時は対応LPへリダイレクト |

cases が悪いのではなく、**デモ/業種の説明双子になっている**のが問題。LPができれば置き場所が無くなる。

## 4. W型 / F型の定義

| 型 | 意味 | 公開での位置 | 例 |
|---|---|---|---|
| **W型** | 業種・オファー単位の説得LP（現場の楔→体験→導入） | **TOP本線の着地** | 建設の記録、介護ケア記録 |
| **F型** | 能力・部品パターン単位のLP（ギャラリー部品の説得） | 後段。W型が揃ってから部品カタログ経由で露出 | `voice-to-structured`, `photo-to-classification` |

サイト整理に直結するのは **W型**。  
部品デモ単体を並べると「小さい」印象になり、W型の価値が薄まる。

既存 `/demo/voice-to-structured` 等は F型資産として有用だが、**TOPの4カード着地には使わない**。

## 5. パイロットと展開順（消す前に作る）

置き換えるものが無い状態でページを消すと空白ができる。順序は固定する。

### Phase A — 建設W型を1本作る（最初にやること）

1. 建設の記録デモ向け **W型LP v1.1** を1本作成  
   - 参照ブロック: [`re_demo/lp-block-definition-v1.md`](./re_demo/lp-block-definition-v1.md)  
   - 体験先: 既存外部ハブ（`construction_demo`）  
   - 吸収元: `data/cases/construction-photo-sorting.ts` の説明  
   - 推奨slug案: `construction-records`（確定は実装時。TOPカードの `detailHref` と一致させる）
2. TOPの建設カードだけ  
   - 主ボタン「詳しく見る」→ 建設W型LP  
   - 補助「デモを直接開く ↗」→ 外部ハブ  
   - 「流れを見る」削除
3. 反応を見る（到達・滞在・試算/相談）

### Phase B — 効いたら残り業種

| 順 | 業種カード | W型LP | 外部デモ |
|---|---|---|---|
| 1 | 建設・設備 | 建設の記録 | 建設ハブ |
| 2 | 医療・福祉 | ケア記録 | 介護デモ |
| 3 | 製造 | 製造の判断（またはナレッジ） | 製造ハブ |
| 4 | 小売・サービス | 案内/CS系（準備できてから） | 既存外部 |

※ 小売・製造で外部デモと説明資産の成熟度が足りない場合は、カードは入口のまま・LPはゲート（G1–G6）通過後に公開。

### Phase C — 痩せさせ / 非表示（LPが正本になってから）

1. 活用イメージ詳細を廃止（対応LPへリダイレクト）
2. デモ一覧を索引化（説明を削る）
3. 部品デモの **露出を止める**（消さない）  
   - URLは生かす（営業送付用）  
   - TOP・デモ一覧の本線表示から外す  
   - F型LPと部品カタログができた時点で復活
4. ギャラリー詳細 `/ai-capability-gallery/{slug}` はリダイレクトまたは非公開導線化
5. `/how-we-work` から「デモ別の活用イメージで詳しく読む」本線を外し、LPへ差し替え

## 6. 部品デモの扱い（削除ではなく露出停止）

| 項目 | 方針 |
|---|---|
| デモ本体URL | 残す（今日から営業送付可） |
| TOP / 一覧からの表示 | 外す |
| ギャラリー詳細 | 公開導線から外す（リダイレクト推奨） |
| 復活条件 | 対応F型LPがあり、W型本線を薄めない見せ方ができること |

## 7. CTA規則（全ページ共通）

### 7.1 カード・一覧

- 主ボタンは **1つ**
- 補助はテキストリンク **最大1つ**（体験の最短経路）
- 「体験 / 詳しく / 活用イメージ / 流れ / 見積 / 問い合わせ」を横並びしない

### 7.2 LP内

LP内の意思決定CTAは原則:

1. 試算（B11 / `#roi` または外部ROI kit）
2. 相談（フォーム or `/contact`）
3. （副）いますぐデモを触る ↗

「次に進む」で4〜5本の同等ボタンを並べない。

### 7.3 相互リンク禁止リスト（公開ナビ）

次の相互誘導を本線にしない。

- ギャラリー詳細 ⇄ cases 詳細 ⇄ `/demo` 詳細の三角関係
- cases 詳細の「簡易デモ / 詳しく / 業務デモ / 概算」同等4ボタン
- LPから cases 詳細へ「続きの説明」として飛ばすこと

## 8. コンテンツ移行マップ（cases → LP）

| 旧casesの要素 | LPブロック |
|---|---|
| `pain` / before 要約 | B01 ヒーロー、B04 コストの正体 |
| `before` / `after` steps | B08 結果イメージ、B09 差分 |
| `fit.goodFor` / `notIdealFor` | B05 効く条件 / 効かない条件 |
| `outcomes` | B03 柱、B08 |
| `demoScope` | B08注記、FAQ（準備・精度） |
| `externalDemo` | ヒーロー副CTA / B14体験併記 |
| 業種ストーリー | B06（必要な場合） |

単一ソース原則: 数字・試算は ROI Config。LPに金額直値を増やさない（ブロック定義 P1/P4）。
