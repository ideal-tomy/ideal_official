## B05 効く条件

| 項目 | テキスト |
|---|---|
| ラベル | 効く条件 |
| 見出し | この仕組みが効く会社は、はっきりしています |
| リード | 業種でも工種でもなく、「誰から誰へ渡るか」で決まります。 |

| # | 役割 | 条件 | 本文 |
|---|---|---|---|
| 1 | 現場監督・職長 | 現場で撮る人がいる | 工事写真・状況写真を、スマホやデジカメで日常的に記録している。 |
| 2 | 内勤・工務 | 事務所でまとめる人が、別にいる | 撮った本人とは違う誰かが、報告書・台帳・提出書類の形にしている。 |
| 3 | 所長・現場代理人 | 出す前に確認する立場がある | 提出先（元請・発注者・監査）へ出す前に、内容を見て通す/戻す判断をしている。 |

- 注記: 工種・現場数・提出様式・いま使っているツール（LINE、メール、Excel、紙）は一切問いません。
- 肯定: 3つが揃っているなら、この仕組みは乗ります。バトンが一方向に渡る現場なら成立するように設計されています。
- 除外: 逆に、一人親方で撮影から提出まで一人で完結している場合や、写真提出の義務がない工事だけを扱っている場合は、フロー化の価値は出ません。その場合は写真の整理機能だけで十分です。

## B13 FAQ

**コンポーネント直書き**

- ラベル: FAQ
- 見出し: よくある質問

| # | 質問 | 回答 |
|---|---|---|
| 1 | 現場ごとに写真の撮り方も呼び方もバラバラです。本当に対応できますか。 | はい。どんな写真でも読める万能ツールを売るのではなく、御社の呼び方を学習させるやり方だからです。現場ごとの呼び方・略語は運用しながら辞書に乗せていきます。 |
| 2 | 料金はいくらですか。 | 導入範囲（部品・現場数・連携）で変わります。部品単位の概算は相談または見積シミュレーターで確認できます。このページの試算で規模感をつかんだうえで、詳細は /estimate またはお問い合わせへ。 |
| 3 | 写真が大量にあります。AI利用料が膨大になりませんか。 | 処理は取り込み時に一度だけ行う設計です。使うほど辞書が育ち、同じ判断のやり直しが減る方向に寄せます。 |

## 付録 B: 表現を揃えるときの進め方（提案）

「全部の日本語を一度に磨く」は難しいので、**層を分けて**進めると迷いが減ります。

### 1. 正本を1つに決める

- **軸（見出し・ヒーロー）:** `../archive/copy-construction-record-v2.md` の語彙ルールを正本にする
- **実装:** `construction-record.ts` が表示の正本（この一覧はその写し）
- **図解:** SVG は軸に直結するので、CONFIG より優先して揃える（transcribe-cost ↔ ヒーロー）

### 2. 直す順序（おすすめ）

1. **コンポーネント直書き** — B08 見出しなど CONFIG にない文言（少ない）
2. **図解 SVG** — ページの半分を占めるので、ここが揃うと体感が一気に変わる
3. **第2弾ブロック** — B05・B06・B12・FAQ（v2 文案は既にある）
4. **部品カタログの seamRemoved** — 内部用ラベルだが「継ぎ目」が目に入る

### 3. 統一ルールは「禁止リスト」より「置き換え表」

全文を同じトーンにするのではなく、**同じ意味の言い方を1つに固定**する。

| 使う | 使わない（この LP では） |
|---|---|
| 書き写す（見出し軸） | 転記（ユーザー向け文案では） |
| 流れ / この仕組み | ワークフロー / フロー化 |
| 要りません | 不要（混在させない方がよい） |
| 工事写真台帳（初出で定義後は台帳可） | 写真台帳だけで初出 |
| うまくいかない理由 | 壁を壊す |

- **1ブロック = 1コミット**（B12 だけ、FAQ だけ）
- 変更後はこの `construction-record-lp-text-inventory.md` を更新して差分を見る

所長・工務が上から読むとき、**ヒーロー → B04 図 → B02「1回」** が同じ物語になっていれば、細部の「要りません/不要」レベルの揺れは許容できます。まず **軸3点**（書き写す・1回記録・撮り直せない）の整合を取るのが効果が大きいです。
