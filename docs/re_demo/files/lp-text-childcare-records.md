## どのような園に向いているか

| 項目 | テキスト |
|---|---|
| ラベル | どのような園に向いているか |
| 見出し | 転倒やアレルギーの記録を、毎日どこかで書いている園向けです。 |
| スコープ注記 | いまの帳票や連絡手段を、いきなり全部やめる必要はありません。報告書の下書きから始められます。 |

### 条件

| No | 役割 | タイトル | 本文 |
|---|---|---|---|
| 1 | 現場 | 記録すべき出来事が日常にある | 転倒・アレルギー・子ども同士のトラブルなど、残す出来事がある。 |
| 2 | 報告 | 報告書や保護者連絡がある | 対象・時刻・対応・連絡文など、書く項目が決まっている。 |
| 3 | 確認 | 園のマニュアルに沿って残したい | どの指針に沿った対応かを引用した形で、人が確認して確定したい。 |

- **当てはまる場合:** この3つに当てはまる場合、記録と報告にかかる時間を減らせます。
- **当てはまらない場合:** 介護施設のケア記録は別のデモ（ケア記録デモ）が対象です。子どもの状態の判断そのものを自動化したい場合は向きません。

## 改訂メモ（第2版）

**今回の変更**

- **ヒーローの価値軸を層1（書く時間が減る）から層2（記録の時間が減り、全員が同じ内容を見て話せる）へ変更**しました。ただし「保育の質が上がる」「関わりが豊かになる」とは書いていません。戻るのは時間までで、その時間を何に使うかは園が決めることです。そこまで約束すると、園長には現場を知らない書き方に見えます
- **「誰の仕事が変わるか」セクションを新設。** 担任・主任と園長・保護者の3者で書いています。closing で「その時間を何に使うかは、園が決めることです」と止め、離職や定着には触れていません。園長は自分でそこまで読みます
- **音声入力を主機能として前面に出しました。** 第1版では「マイク実録音は不要」「録音は不要」と書いており、主力機能を打ち消す文言になっていました。製品の説明（口頭で数行残す）と、デモの都合（体験はシナリオで進む）を分け、後者は「デモ注記」という別項目にしています。`.ts` に項目追加が必要です
- 音声を前面に出したことで必ず出る不安を、FAQに2問追加しました（保育中に話しかけるのは現実的か／子どもの声も録音されるか）。後者は園にとって重い論点なので、こちらから先に触れています
- **インパクトを金額から時間の表示に変更**しました。「子どもと向き合う時間を増やす」という見出しと、金額を主表示にしたインパクトは噛み合いません。金額は根拠注記に落としています。ROIシミュレーター側も、時間を主表示にする改修が必要です

**要確認**

- 初期値を第1版で **20人・時給2,500円** → **15人・時給1,800円・250開園日** に変更しています。シミュレーター側の初期値も合わせてください
- 音声入力が本番機能としてどこまで想定されているか。層2の1行目、機能01、FAQ2問がこれを前提にしています。構想段階なら「口頭で残す」を「その場で残す」に戻し、FAQ2問を削ってください
- 録音データを保存するかどうか。FAQでは「園のルールに合わせて設計」としていますが、方針が決まっているなら明記したほうが安心されます

## 改訂メモ（第3版・言い回しの整理）

判定基準: その表現を、営業担当者が打ち合わせで口に出して言うか。

- 記録に取られている時間を、子どもの前に戻す → 記録にかかる時間を減らして、子どもと向き合う時間を増やす（見出し・OGP）
- 子どもを見ている時間が削られています → 子どもを見ている時間はその分減っています
- どこに沿った対応かを添え → どこに沿った対応かを一緒に表示し
- 年間で何時間かが出ます → 年間の合計が出ます
- 図alt: 記憶を経由していた情報が〜形になる → 担任の記憶に頼っていた情報を、全員が同じ記録で見る
- 共通ブロック: 作る範囲を言葉にし → 作る範囲をはっきりさせて／価格レンジ → おおよその費用／業務に載せる形へ → 実際の業務で使える形に／伴走します → 一緒に進めます
