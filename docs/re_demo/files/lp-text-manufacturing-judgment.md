## どのような部署に向いているか

| 項目 | テキスト |
|---|---|
| ラベル | どのような部署に向いているか |
| 見出し | 同じ質問が毎週のように来る部署向けです。 |
| スコープ注記 | 全社の文書をいきなり全部取り込む前提にはしません。対象にする文書の範囲と、誰が見られるかを決めてから進めます。 |

### 条件

| No | 役割 | タイトル | 本文 |
|---|---|---|---|
| 1 | 現場 | 同じ問い合わせが繰り返される | 手順・優先順位・連絡先など、似た質問が毎週のように発生している。 |
| 2 | 文書 | 規程や手順書が文書として存在する | 口頭だけの知識ではなく、参照できる文書がある（内容が古くても構いません）。 |
| 3 | 確認 | 何を根拠に答えたかを残したい | 答えだけでなく、その根拠まで残す運用にしたい。 |

- **当てはまる場合:** この3つに当てはまる場合、探す時間と、人によって答えが変わる状態を減らせます。
- **当てはまらない場合:** 文書がほとんどなく口頭だけで運用している場合、人が確認せずに回答を最終決定に使いたい場合、権限を決めずに機密文書まで横断検索したい場合は向きません。

## 改訂メモ（第2版）

**今回の変更**

- **「誰の仕事が変わるか」セクションを新設。** ただしこのページは、**属人化からの脱却／本質的な業務への集中とは書いていません。** 「ベテランの知識を仕組みに移す」という趣旨は、読み手がベテラン本人や管理者の場合、自分の価値を減らす提案に読めます。書いたのは「同じ質問に何度も答えなくてよくなる」という、その人自身にとっての利得だけです
- 同じ理由で、closing に「判断そのものを置き換えるものではありません」という歯止めを入れ、FAQにも「ベテランの判断を置き換えるものですか？」を追加しています
- ヒーローは変更していません。4本のうちこのページだけ、価値軸が層1（探す時間そのもの）で成立するためです
- 3つ目の立場を「異動・中途で入った人」にしています。ここは新しく入る人が自分で調べられるという利得で、誰の立場も削りません

**要確認**

- 数字のプレースホルダ（◯◯◯万円）は表示例です
- 「03 判断を残す」は、人が確定した回答を再利用する機能です。デモに該当する動作がなければ、この項目と層2セクション2行目（「一度確認した答えが残り」）を実装に合わせて弱めてください
- 40人という初期値が、工場全体か特定部署かで説得力が変わります

## 改訂メモ（第3版・言い回しの整理）

判定基準: その表現を、営業担当者が打ち合わせで口に出して言うか。

- 箇所を添えて返します → 箇所も一緒に表示します（「添えて返す」は書き言葉）
- 手がかりをそろえます → 短時間で見つけられます
- 出典が残っていれば → どこに書いてあったかが残っていれば
- 図alt: 判断が先に進む → その場で判断できる／質問の線が分かれる → 質問が減る
- 文書を載せます → 対象に含めます
- 共通ブロック: 作る範囲を言葉にし → 作る範囲をはっきりさせて／価格レンジ → おおよその費用／業務に載せる形へ → 実際の業務で使える形に／伴走します → 一緒に進めます
