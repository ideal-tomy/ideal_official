# Cursor 依頼用 指示文 ─ ideal公式サイト UI修正

対象: `https://ideal-official-three.vercel.app/cases`（活用イメージ）を中心とした修正

---

## 使い方

- **必ず1タスクずつ貼ること。** まとめて貼るとAutoが途中で対象を見失います。
- 各タスク完了後に `npm run build` を通し、コミットしてから次のタスクへ。
- 各プロンプトは「対象ファイルの特定 → 計画提示 → 実装」の順に組んであります。ファイルパスを自分で書く必要はありません。
- 想定と違うファイルを報告してきた場合は、そこで止めて正しいパスを教えてください。

---

## タスク1 ─ 見出しの改行崩れを直す

```
【タスク】/cases ページのヒーロー見出しの改行崩れを修正する

【現象】
見出し「自社の仕事に、置き換えてみる。」が3行に折り返され、
最後の「る。」だけが単独で3行目に落ちている。

【手順】
1. この見出しを出力しているコンポーネントファイルを特定し、パスを報告すること。
2. 実装計画を3行以内で示すこと。
3. 承認を待たず、そのまま以下を実装すること。

【実装内容】
(A) 該当の見出し要素の中身を、文節ごとに inline-block の span で包む。
    既存の className は一切変更せず、中身だけ差し替える。

    <h1 className="（既存クラスをそのまま維持）">
      <span className="inline-block">自社の仕事に、</span>
      <span className="inline-block">置き換えてみる。</span>
    </h1>

(B) グローバルCSS（app/globals.css 等）の末尾に以下を追記する。
    既存の指定は削除・変更しないこと。

    h1, h2, h3 {
      word-break: auto-phrase;
      line-break: strict;
      text-wrap: balance;
    }

【禁止事項】
- font-size / color / margin / padding など他のスタイルを変更しないこと
- 見出しの文言を変更しないこと
- /cases 以外のページのコンポーネントを変更しないこと

【完了条件】
- ブラウザ幅 1440px / 768px / 375px の3つで、見出しが最大2行に収まること
- 1文字だけが単独行に落ちていないこと
- npm run build がエラーなく通ること
```

## タスク2 ─ 業種セクションをカードグリッドにする

> もとの「2. カードグリッド化」と「3. ストライプ背景の統一」は同じコードを触るため、1タスクに統合しています。分けると2回目が1回目を壊します。

```
【タスク】/cases ページの業種セクションを、帯レイアウトからカードグリッドに変更する

【現状】
建設・介護・農業・法務・小売・バックオフィス・社内 の7業種が、
それぞれ画面幅いっぱいのセクション（帯）として縦に並んでいる。
背景色が白と薄い青で交互に切り替わっている。

【手順】
1. 7業種のデータを保持している箇所（配列 / JSON / MDX など）と、
   それをレンダリングしているコンポーネントを特定し、両方のパスを報告すること。
2. 実装計画を3行以内で示すこと。
3. 承認を待たず、そのまま実装すること。

【実装内容】
(A) データ構造（業種名・タグ・見出し・補足文・リンク先）は変更しない。
    レンダリング部分のみ差し替える。

(B) 7業種を1つの grid にまとめる。変数名は既存コードに合わせること。

    <div className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
      {industries.map((item) => (
        <a
          key={item.slug}
          href={item.href}
          className="block rounded-2xl border border-slate-200 bg-white p-6
                     transition duration-200
                     hover:border-slate-400 hover:-translate-y-0.5"
        >
          <p className="text-xs text-slate-500">{item.tag}</p>
          <h3 className="mt-2 text-lg font-bold leading-snug">{item.title}</h3>
          <p className="mt-2 text-sm text-slate-500">{item.sub}</p>
        </a>
      ))}
    </div>

(C) 業種ごとの交互背景色（白／薄い青）の指定を削除し、
    セクション全体の背景を1色に統一する。

(D) セクション全体を max-w-6xl mx-auto px-4 で囲む。

(E) このプロジェクトは既にダークモードに対応している。
    カードの bg / border / text に対して、
    既存コンポーネントで使われているのと同じ記法
    （dark: プレフィックス もしくは CSS変数）で
    ダークモード時の指定を必ず併記すること。
    記法は既存ファイルを読んで揃えること。新しい方式を導入しないこと。

【禁止事項】
- 業種の数・順序・文言を変更しないこと
- リンク先URLを変更しないこと
- セクション上部の「業種から選ぶ」ピル（タブ）部分には今回触らないこと
- 新しいライブラリを追加しないこと

【完了条件】
- 1440px で3列、768px で2列、375px で1列になること
- 7業種すべてが表示され、リンクの遷移先が従来と同一であること
- 交互の背景ストライプが消えていること
- ライトモード・ダークモード両方でテキストが読めること
- npm run build がエラーなく通ること
```

## タスク3 ─ ヒーローの余白と縦位置を整える

```
【タスク】/cases ヒーローセクションの余白と縦位置を調整する

【現状】
- ヒーロー下部（「業種から探す」ボタンの下）に不要な空白が大きく残っている
- 左のテキストブロックと右のビジュアル画像の縦中心が揃っていない

【手順】
1. ヒーローセクションのコンポーネントを特定し、パスを報告すること。
2. 現在ヒーローに当たっている高さ・余白の指定を列挙して報告すること。
3. そのまま実装すること。

【実装内容】
(A) ヒーローに min-h-screen / h-screen / min-h-[100vh] 等の
    ビューポート高さ指定があれば削除する。
    代わりに縦paddingを py-[clamp(72px,10vh,128px)] にする。

(B) 左右2カラムを包んでいる flex または grid のコンテナに
    items-center を指定し、テキストとビジュアルの縦中心を揃える。

(C) 768px未満では従来どおり1カラム縦積みを維持すること。
    その際は items-center の影響で崩れないか確認すること。

【禁止事項】
- ヒーローの画像ファイル自体を差し替えないこと
- 見出し・本文・ボタンの文言を変更しないこと
- タスク1で追加した span の構造を壊さないこと

【完了条件】
- 1440px でヒーロー下部の余白が視覚的に不自然でないこと
- 左テキストと右ビジュアルの縦中心が揃っていること
- 375px で縦積みレイアウトが崩れていないこと
- npm run build がエラーなく通ること
```

## タスク4 ─ ロゴとハンバーガーの白いチップを消す

```
【タスク】ヘッダーのロゴとハンバーガーボタンに付いている白い角丸背景を削除する

【現象】
スマートフォン表示時、ヘッダーのロゴ「ideal」の背後と、
右上のハンバーガーメニューボタンの背後に、
それぞれ白い角丸の四角形が個別に表示されている。
他の要素と位置・サイズが揃っておらず、未完成に見えている。

【手順】
1. ヘッダーコンポーネントを特定し、パスを報告すること。
2. ロゴとハンバーガーボタンに現在当たっている
   背景・角丸・シャドウ系のクラスを列挙して報告すること。
3. そのまま実装すること。

【実装内容】
(A) ロゴ要素とハンバーガーボタン要素に個別に付いている
    bg-white / bg-*/ rounded-* / shadow-* の指定を削除する。
    ※ ボタンのタップ領域（padding, min-width, min-height）は残すこと。

(B) ヘッダー要素そのものに以下を指定する。
    bg-white/80 backdrop-blur-md border-b border-slate-200

(C) ヘッダーの sticky top-0 z-50 は維持する。

(D) ダークモード時の背景・境界線の指定を、
    既存の記法に合わせて必ず併記すること。

【禁止事項】
- ナビゲーションの項目・順序・リンク先を変更しないこと
- ハンバーガーメニューの開閉ロジックを変更しないこと
- ロゴ画像やロゴテキストを差し替えないこと

【完了条件】
- 375px でロゴ・ハンバーガーの背後に白い四角が表示されていないこと
- スクロール時、ヘッダー背後のコンテンツが半透明に透けて見えること
- ハンバーガーメニューが従来どおり開閉すること
- ライトモード・ダークモード両方でヘッダーが視認できること
- npm run build がエラーなく通ること
```

## タスク5 ─ マスコットの表示条件と位置を直す

```
【タスク】右下の案内マスコットの表示条件・サイズ・位置を修正する

【現象】
右下に固定表示されている案内マスコットが、
ページのどこにいても常時表示されており、本文テキストの上に重なっている。
特にスマートフォン表示で可読性を損なっている。

【手順】
1. マスコットのコンポーネントを特定し、パスを報告すること。
2. 現在の表示条件（常時表示か、何らかの条件付きか）を報告すること。
3. そのまま実装すること。

【実装内容】
(A) 表示条件を変更する。
    ページ最下部から 600px 以内までスクロールされたときのみ表示する。
    条件を満たさない間は opacity-0 pointer-events-none とし、
    transition-opacity duration-300 でフェードさせること。
    要素自体は DOM から外さず、opacity で制御すること。

    判定は useEffect 内の scroll イベントで行い、以下を必ず守ること。
    - addEventListener の第3引数に { passive: true } を指定する
    - クリーンアップ関数で removeEventListener する
    - 判定式: window.innerHeight + window.scrollY >= document.body.offsetHeight - 600

(B) 位置とサイズを調整する。
    - fixed bottom-6 right-4 z-40
    - 表示サイズを現在の 65% に縮小する

(C) ページ最下部のコンテンツ（フッターの直前の要素）に pb-28 を追加し、
    マスコット表示中でも本文と重ならないようにする。

【禁止事項】
- マスコットの画像・セリフ文言・リンク先を変更しないこと
- 既存のクリック挙動を変更しないこと
- z-index をヘッダー（z-50）より大きくしないこと

【完了条件】
- ページ上部・中腹ではマスコットが表示されないこと
- 最下部までスクロールするとフェードインで表示されること
- 表示中、375px で本文テキストと重なっていないこと
- クリック時の挙動が従来と同じであること
- npm run build がエラーなく通ること
```
