- 根拠となるコードと行番号

GitHub、Vercel、Cloudflare、Resend、Sanityを確認してください。

確認する内容：

- 本番ドメインとVercelプロジェクトの対応

## 3. 追加のセキュリティ調査

### 問い合わせ・メール

- 自動返信だけを緊急停止できるか
- 管理者通知を維持できるか
- 送信先メールアドレスごとの制限
- サイト全体の送信上限
- 重複送信の防止
- Resendの送信量と料金上限
- Turnstileのサーバー側検証
- ハニーポットの必要性
- IPアドレスの取得方法と信頼性

### AI API

- 全Gemini APIエンドポイントの洗い出し
- APIごとの入力上限
- APIごとのレート制限
- サイト全体の日次利用上限
- 同時実行数の制限
- タイムアウト
- トークン消費量
- 予算アラート
- APIキーの公開リスク
- プロンプトインジェクションによる意図しない処理や情報開示の可能性

### Sanity・管理機能

- Studioの認証と権限
- 読み取り・書き込みトークン
- 非公開データの露出
- 管理者以外の更新可否
- 公開クエリで取得できる項目
- バックアップ・復元

### インフラ・依存関係

- Next.jsなどの重大脆弱性
- セキュリティヘッダーとCSP
- CORS
- Cloudflareの保護範囲
- GitHubの秘密情報管理
- Vercelのデプロイ保護
- エラーログと個人情報

## 4. 改善作業の分割

すべての問題を一括修正しないでください。

次の単位に分けて実施計画を作成してください。

- Phase 0：本番環境の特定と緊急対策の判断
- Phase 1：重大脆弱性・メール悪用リスクへの対応
- Phase 2：API入力検証・エラー処理・ログ改善
- Phase 3：Turnstile・共有レート制限・送信制御
- Phase 4：AI APIの利用制限と費用対策
- Phase 5：メール認証・Sanity・Cloudflare設定
- Phase 6：統合テスト・本番反映・監視

ただし、実際の重大度によって実施順序は変更してください。

各Phaseについて、次を明記してください。

1. 作業目的
2. 対象ファイル・設定
3. 変更内容
4. 必要な外部サービス
5. 費用が発生する可能性
6. 既存機能への影響
7. テスト項目
8. 完了条件
9. ロールバック方法
10. ユーザーの承認が必要な操作
