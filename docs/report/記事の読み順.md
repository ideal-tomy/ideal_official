# 記事を書くとき、何を読むか

2026-08-23 時点の正本。ここに無いファイルは、記事執筆の前提にしない。

サイトのヘッダー・本文幅などの**見た目の器**は揃えてよい。**節の順番**は記事ごとに別物。同じ構成は手抜きに見える。確認の手順は `.cursor/rules/article-is-one-off.mdc`。

## 用途 → 読んでよいもの

| 用途 | 読む | 読まない |
|---|---|---|
| 業界記事 1 本 | 下の「判定だけ」＋その業界の **公開 HTML**（`content/articles/{slug}.html`） | 他業界の HTML、横断シリーズ計画、archive |
| 悩み・横断 1 本 | 「判定だけ」＋既存横断の **h2 一覧だけ**（同じ並びを禁止するため） | シリーズ計画のレイアウト節、業界9本の本文 |
| ハブ・目次 | `data/articles/index.ts` とハブコンポーネント | 記事本文ルールの章立て |
| LP・デモ | それぞれのルール（W型 / Demo Standard） | このファイルと記事制作ルール |
| 過去の調査・失敗ログ | ユーザーが「あれを見て」と言ったときだけ | 常時 |

公開の正本は HTML。`*_revised.md` は文の控え。両方あるときは HTML を直す。

## 判定だけ（記事制作ルールから使う節）

全文を読まない。次だけ。

1. デモリンクを消しても読む価値があるか
2. IT なしで明日できることが一つか
3. 主語は仕事か（導入の話になっていないか）
4. 法令を書くなら出典 URL
5. DX / FAQ 語を使わない。見出しは作業名

パス: [記事制作ルール.md](./記事制作ルール.md) の 0・1・3。**2（形のレシピ）を共通テンプレとして使わない。**

## 新しい記事のメモに書いてよいこと / 書いてはいけないこと

**よい:** 職場、止まっている物、明日の一手、出典、slug  
**いけない:** 表紙は全幅色面、直後に食い違い1塊、h2 を何章にする、他記事と同じ締めの位置
