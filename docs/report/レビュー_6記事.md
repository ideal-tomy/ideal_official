# 6記事レビュー ― ITに詳しくない社長が読んで分かるか

対象: 建設 / 製造 / 医療・介護 / 保育 / 小売 / 飲食　の6本（HTMLの表示テキスト全文）
見る観点: 日本語として読めるか、何ができるのか分かるか、次の行動に進めるか

---

## 1. 全体の結論

### よくできている点

6本とも「なぜうまくいかないのか」の説明は明快です。
専門用語もほとんど使っておらず、社長が自分の会社の話として読めます。
特に、冒頭で読者の実感（現場から言われた言葉、シフト表、受信箱）から入る作りは、
どの業界でも通用します。

### 致命的に足りない点

**6本とも、「結局うちに何が入るのか」が一行も書かれていません。**

いま6本が伝えているのは、次の三つだけです。

1. うちの業界では、こういう理由でうまくいかない
2. だから、こういう順番でやるといい
3. 画面があるので触ってください

ITに詳しくない社長がここで止まります。理由は単純で、**買うものの正体が分からない**からです。

読み終わったあと、次の疑問が全部残ります。

- ソフトを買うのか、アプリを入れるのか、人に来てもらうのか
- いま使っているシステムは、捨てるのか、そのまま残るのか
- 誰が、どの機械で、何をするようになるのか
- いくらくらいで、どれくらいの期間で始まるのか
- 使い方は誰が現場に教えるのか

これが分からないまま「相談する」を押せる社長は、そう多くありません。
逆に言うと、ここを足すだけで反応はかなり変わるはずです。

## 2. 全記事に共通する言葉の問題

### 2-1. 「デモ」が通じない

6本すべてで「デモを開く」「実際の画面」「触ってみる」を使っています。
このうち **「デモ」は、ITに詳しくない層には通じにくい言葉**です。
展示会でよく聞くので何となく分かる、という程度で、
「見るだけのもの」なのか「自分で操作するもの」なのかが伝わりません。

言い換え案:

| いまの表現 | 変える案 |
|---|---|
| デモを開く | 実際に動かしてみる |
| 実際の画面 | 実際に動く画面 |
| 触ってみる | スマホでそのまま試せます |
| 体験版 | お試し用に用意したものです |

「触ってみる」も、それ自体は悪くありませんが、
何をどう触るのかが書かれていないと動作が想像できません。

### 2-2. 「DX」「ICT」が混ざっている

- 製造 … タイトル横に「製造業のDX」、本文にも「DX」が2回
- 小売 … 「中小企業でDXがうまくいっていない割合は64%」
- 医療介護 … タイトル横に「医療・介護のICT」
- 建設 / 保育 / 飲食 … どちらも使っていない

**使っていない3本のほうが読みやすいです。**
DXもICTも、社長は聞いたことはあっても、
自分の会社で何が起きることなのかは分かっていません。

「新しい仕組み」「記録ソフト」「システム」など、
その記事で扱っている具体物の名前に置き換えるのが確実です。

### 2-3. 記事ごとに引っかかる言葉

| 記事 | 気になる語 | 言い換え案 |
|---|---|---|
| 建設 | 自分の会社だけを電子にしても | パソコンで扱えるようにしても |
| 製造 | 稟議 | そのままで可（社長には通じる） |
| 製造 | 三千万が高いのか安いのか | 金額の例は消す。自社の価格と誤解される |
| 医療介護 | 内勤 | 事務所の職員 |
| 医療介護 | 仮の仕組みで動いています | 本物のAIではなく、用意しておいた答えが出ます |
| 小売 | 自社のFAQを入れて | よくある質問をまとめた文章を入れて |
| 小売 | 根拠になった案内文といっしょに | どの案内文を見て答えたかも一緒に |
| 保育 | （問題なし） | ― |
| 飲食 | （問題なし） | ― |

保育と飲食は、言葉の面ではほぼ直すところがありません。
この2本を基準にすると、他の4本の直し方が決めやすいです。

## 3. タイトルが分かるか

読んだ瞬間に「何の記事か」が分かるかどうかで並べました。

| 記事 | タイトル | 判定 |
|---|---|---|
| 建設 | 建設の現場で、新しい仕組みが続かない理由。 | ◎ 何の話か即分かる |
| 飲食 | ツールを増やしたのに、店長の仕事は増えた。 | ◎ 状況も結論も分かる |
| 保育 | 機能を増やすほど、先生の手間は増えます。 | ◎ 主張がそのまま出ている |
| 小売 | 昨日届いた問い合わせを、並べてみてください。 | ○ 呼びかけとしては良いが、何の記事かは分からない |
| 医療介護 | 入れている施設は4分の3。楽になったのは、半分。 | △ 「入れている」の中身が書かれていない |
| 製造 | その工程を説明できる人は、あと何人ですか。 | × 何の記事か分からない |

**製造は、建設で直したのと同じ問題が残ったままです。**
質問だけを投げるタイトルは、答えを知らない人には意味が取れません。
しかも記事の中身は「決裁が進まない理由」なので、タイトルと中身がずれています。

案: 「製造業で、システムの導入が決まらない理由。」

医療介護も「記録ソフトを入れている施設は4分の3。」のように、
何を入れているのかを一語足すだけで通じるようになります。

## 4. 記事ごとの評価

### 建設　◎

6本でいちばん整っています。

- 冒頭で「理由は二つ」と予告 → 理由1 → 理由2 → その答え、という順番が守られている
- 理由2で出した「会社をまたぐ」問題に、後半で戻って答えている
- 「三つの条件」が具体的で、社長が自社に当てはめられる

**足りないもの**: 写真を撮ったあと、誰がどこで何をするのかが書かれていません。
「写真から報告書ができる」とありますが、
撮るのは現場、直すのは誰か、出す先はどこかが不明です。

### 飲食　◎

シフト表を最初に見せる作りが効いています。
「一人休むと一コマでは済まない」が、文章を読まなくても分かります。

**足りないもの**: スタッフ側が何をするのかが書かれていません。
「希望を集める」とありますが、パートさんがスマホで入力するのか、
紙で出したものを店長が入れるのかが分かりません。
ここは高齢のスタッフを抱える店ほど気にする点です。

### 小売　◎

**ITに詳しくない社長にいちばん届くのはこの記事です。**
受信箱を10件並べて7件と3件に分ける作りは、説明が要りません。

「人を減らす話ではなく、残りの3件に時間を回す話」と書いているのも良いです。
自動化の記事でいちばん警戒されるところを、先に打ち消せています。

**足りないもの**: 「よくある質問をまとめた文章を入れる」と書いていますが、
それが何ページくらい必要なのか、誰が作るのかが分かりません。
ここは「作るのが大変そう」で止まる人が多い部分です。

### 保育　○

言葉はいちばん平易です。12個→3個→1個と絞る流れも分かりやすい。

**問題**: 最後まで読んでも、園が何を入れることになるのか分かりません。
しかもお見せする画面が保育向けではないので、行動が起きにくい構成です。

正直に書いた判断は正しいですが、
その代わりに「保育向けはこういう形で作ります」という一段落が要ります。
いまは、断ったまま終わっている状態です。

### 医療・介護　△

数字を二つ並べる入り方は良いのですが、中盤に読みにくい箇所があります。

**往復の図が伝わりにくい**。
縦線が三本あって、線が行き来しているのは分かりますが、
「何が」行き来しているのかが図からは読み取れません。
本文を読んで初めて意味が分かる状態です。

図の中に「同じ内容の確認が6回」と直接書いたほうが確実です。

**「仮の仕組みで動いています」も伝わりません。**
本物のAIではない、という意味ですが、この言い方では分かりません。

### 製造　×

**6本で唯一、書き直す前の状態のまま残っています。**

- タイトルが質問形で、何の記事か分からない
- 「DX」を使っている
- 記事の中身が「決裁が進まない理由」に寄りすぎていて、何ができるのかが薄い
- 「三千万」という金額が、自社の見積もりと誤解される危険がある
- 「その人の私物になります」は言葉が強い。社長にとってはベテラン職人を否定された印象になりうる

優先して直すべきはこの記事です。

## 5. 何を足すべきか

### 5-1. 全記事に、同じ位置に同じブロックを入れる

デモへの導線のすぐ下に、次の3行を置きます。

```
何を使うか　　いまのスマホでそのまま使えます
今のシステム　入れ替えは不要です。そのまま残ります
どれくらいで　早ければ1か月ほどで、1つの現場から始められます
```

内容は業界ごとに変わりますが、**答える項目は6本とも同じ**にします。
ここが埋まっていないと、社長は判断できません。

### 5-2. 「誰が何をするか」を一文入れる

各記事のデモ紹介の中に、動作を一つだけ書きます。

- 建設 … 現場で写真を撮って送る。事務所が中身を直して出す
- 製造 … ベテランに聞いた内容を打ち込んでおく。あとから誰でも引き出せる
- 医療介護 … その場で声に出す。事務所で内容を確認して確定する
- 保育 … 保育中に一言だけ声に出す。帰る前に直して出す
- 小売 … よくある質問をまとめた文章を渡す。それをもとに自動で返す
- 飲食 … スタッフがスマホで希望を出す。店長が案を確認して確定する

これがあるだけで、想像できる社長がかなり増えます。

### 5-3. 金額の話を、一段だけ入れる

「いくらか分からないものは相談できない」という壁があります。
正確な金額は出せなくても、次のどれかは書けるはずです。

- 一つの現場・一つの店から始められること
- 全社で入れる必要はないこと
- 最初にかかるものと、毎月かかるものが分かれていること

いまは6本とも金額に一言も触れていないので、
「高そうだから、うちには無理だろう」で終わる可能性があります。

## 6. 直す順番

1. **製造を書き直す**（6本で唯一、他と水準がそろっていない）
2. **「デモ」という言葉を、6本すべてで言い換える**
3. **「何を使うか／今のシステム／どれくらいで」の3行を、6本すべてに足す**
4. **医療介護の図に、何が行き来しているかを書き込む**
5. **保育に、保育向けをどう作るかの一段落を足す**
6. 細かい言い換え（2-3の表）

1と2と3は、今日中にやっても半日かかりません。
4以降は、実際に社長に読んでもらってからでも間に合います。

## 7. 最後に

6本を通して読んで感じたのは、**問題を言い当てる力に対して、
自分たちが何を提供するかの説明が弱い**ということです。

いまの記事は「あなたの会社ではこういうことが起きています」までで止まっていて、
「だから、うちはこれを持っていきます」がありません。

読んだ社長は、たしかに「そうそう、うちもこうだ」とは思います。
ただ、そこから「では話を聞こう」に進むには、
持っていくものの正体が見えている必要があります。

デモを触ればそれは分かるのですが、
**ITに詳しくない社長ほど、デモを開かずに帰ります。**
だから、文章のほうにも一段だけ書いておく必要があります。
