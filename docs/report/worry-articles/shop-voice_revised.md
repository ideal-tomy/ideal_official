# 現場の音声を、そのまま入れられない。

「ベテランの話を録音して、手順書にできたら楽になる」

そう考える会社は多いと思います。

実際、紙に書いてもらうより、作業しながら話してもらった方が早いことがあります。

たとえば、

「ここは音が変わったら止める」

「この角度だとズレやすい」

「新人はここを急ぎすぎる」

こうした話は、手順書だけでは残りにくいものです。

だから、音声から整理できたら便利です。

ただ、現場で実際に録音してみると、別の問題が出ます。

作業の話だけを録るつもりでも、

「〇〇商事向けの部品だから」

「この図面の番号は――」

「前回の不良値が――」

といった話が、普通に入ってきます。

録音を始めたあとで、

「これ、外のサービスに入れて大丈夫なのか」

と止まる。

ここが、現場の音声を扱うときの最初の壁です。

## 録音する前に、四つだけ決める

最初に考えたいのは、AIの性能ではありません。

録音したものを、どこまで扱っていいのかです。

まず、次の四つを決めます。

1. 会社として録音してよいか
2. 誰の声を、何のために残すのか
3. 外に出してはいけない情報は何か
4. どこまで残して、いつ消すのか

元の原稿でも、この四つを「社内ルール・本人の許可・伏せる・必要以上に残さない」という形で整理していました。

この順番は、そのままでいいと思います。

大事なのは、

**録音してから考えないことです。**

あとから、

「やっぱりこれは使えません」

となると、もう一度同じ話をしてもらう必要があります。

ベテランの方に何度も同じ説明をお願いするのは、現場では簡単ではありません。

## 現場の音声には、作業の知恵以外も入ります

録音には、必要な情報だけが入るわけではありません。

たとえば、

- 取引先の名前
- 品番
- 図面番号
- 不良の数値
- 設備の設定値
- 社内だけで使っている呼び方
- その場にいた人の名前

こうした情報も、会話の流れで自然に出てきます。

だから、

「現場の知恵を残したい」

という目的と、

「録音したものをそのまま外へ出していい」

という話は別です。

ここを一緒にしてしまうと、

「便利そうだけど、危ないからやめよう」

で終わりやすくなります。

## 全部を入れなくても、できることはあります

ここで一度、作業を二つに分けます。

一つは、**質問を作ること**です。

たとえば、

「この工程で新人がよく間違えるところはどこですか」

「止める判断は何を見ていますか」

「失敗する前に気づけるサインはありますか」

こうした質問を作るだけなら、品番や取引先名は必要ありません。

工程名と、何を残したいのかが分かれば作れます。

もう一つは、**話してもらった内容を整理すること**です。

こちらは実際の現場情報が入ります。

だから、

質問を作るところまでは外のサービスで使う。

実際の音声を扱うところは、伏せてから使う。

または、社内で閉じた環境にする。

このように分ければ、

「全部使えるか、全部使えないか」

の二択ではなくなります。

## 先に質問を作るだけでも、かなり変わります

現場でよくあるのは、

「とりあえず録音してみよう」

から始めることです。

でも、何を聞くか決めずに録音すると、話が広がります。

昔の話。  
別工程の話。  
別の製品の話。

もちろん、それも大事な情報です。

ただ、手順書を作る目的なら、あとから整理する量が増えます。

なので、最初に質問だけ作っておく方が楽です。

たとえば、

- この作業は、どこから始まりますか
- 一番失敗しやすいところはどこですか
- その失敗は、何を見れば気づけますか
- 新人に最初に伝えることは何ですか
- 絶対に省いてはいけない確認は何ですか

このくらいで構いません。

録音の前に質問があれば、話す側も答えやすくなります。

聞く側も、どこまで聞けば終わりなのか分かります。

## 一工程だけで試す

全部の工程を一度に残そうとすると、止まりやすくなります。

最初は一つで十分です。

「この人が休むと、誰も分からなくなる」

そんな工程を一つ選びます。

そこで、

誰に聞くか。  
何を聞くか。  
何を伏せるか。  
どこまで残すか。

を決めます。

一つやってみると、

「この情報は外に出せない」

「この部分は質問だけなら使える」

「ここは社内で整理した方がいい」

という線が見えてきます。

最初から会社全体のルールを完璧に決めなくても構いません。

## 社内で説明するときは、「録音をAIに入れたい」では伝わりにくい

この話を社内に持っていく担当者なら、

「ベテランの音声をAIに入れたいです」

と言うと、不安が先に出ることがあります。

何を入れるのか。  
どこへ送るのか。  
誰が聞けるのか。  
取引先名は大丈夫なのか。

聞かれることが増えます。

それよりも、

**「ベテランしか分からない作業を、一工程だけ残したいです」**

から始めた方が伝わります。

そのうえで、

「いきなり音声を外へ出すわけではありません」

「まず質問だけ作ります」

「録音する場合は、品番や取引先名を入れない方法を決めます」

「実際に使う範囲は、社内ルールを確認してから決めます」

と説明する。

これなら、

AIを使うかどうかではなく、

**会社の中に残っていない知識を、どう残すか**

という話になります。

経営者も判断しやすくなります。

## 便利そうなのに、現場で止まりやすい理由

音声を文字にすること自体は、以前より簡単になりました。

そこから要点をまとめることもできます。

それでも、現場ではすぐに使えないことがあります。

理由は、技術よりも、

**何を入れてよくて、何を入れてはいけないかが決まっていない**

からです。

便利だから使う。

危なそうだから全部やめる。

この二つの間に、

「ここまでは使う」

という線を引く必要があります。

その線を決めるところが、実際には一番大事です。

## 自社の音声を入れずに、流れだけ試せます

こちらで用意した手順書と検査記録を使って、

- 工程を選ぶ
- 質問が出る
- 回答を整理する
- 急所をまとめる

という流れだけを試せます。

自社の録音は使いません。

[聞き取ったものを引き出してみる](https://product-flowideal.vercel.app/manufacturing)

3分ほどで終わります。登録は要りません。

実際に触ってみると、

「質問を作るところまでは使えそう」

「整理する部分は社内だけで使いたい」

という分け方を考えやすくなります。

## 最初に決めるのは、AIではなく扱い方です

現場の音声を残したい。

その考え自体は、難しいものではありません。

ただし、

録音できるか。  
誰の許可が必要か。  
何を伏せるか。  
どこまで残すか。

ここを飛ばすと、途中で止まります。

逆に、ここが決まれば、

全部を外へ出さなくてもできることが見えてきます。

質問を作る。  
一工程だけ聞く。  
外に出せない情報を除く。  
必要な部分だけ整理する。

まずはそのくらいからで十分です。
